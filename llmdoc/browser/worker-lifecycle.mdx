# 扩展服务的启动与保活

浏览器服务运行于扩展的 MV3 service worker，而不是页面脚本。`extension/src/service_worker.ts` 读取当前 profile 的扩展 storage 配置，构造并启动 JS `ModCDPServer`；权限由扩展清单和实际浏览器策略决定。Node 依赖安装成功不能证明浏览器端能力可用。

MV3 扩展 worker 不支持模块顶层 `await`；读取 bridge 配置必须放在异步启动函数内，再从同步模块入口调用并记录启动错误。TypeScript 编译或打包成功不能替代真实浏览器的 worker 启动验证。

## 启动选择先于远端配置

ReverseWS 与 NATS 的启用值由资源构建注入；服务器据此决定要创建哪些 downstream。Native Messaging 是默认候选，但其宿主是否可用是另一前提。`Mod.configure` 更新已有服务的客户端、路由、注册项和 transport 配置，不负责把未编入启动选择的连接方式凭空启用。

这个边界避免普通扩展默认尝试所有本地可选服务。调整启动方式需重建扩展资源并重载浏览器实际装载的目录；仅重启 Node 代理或发送运行时配置不足以替换旧 worker 的代码和选项。

插件扩展从独立 Release ZIP 由用户手动安装；多个 profile 可以加载同一份扩展文件，连接身份和配置保存在各自 storage，不能由插件向公共扩展目录写入 `bridge-config.json`。普通 profile 向统一的 `127.0.0.1:29393/bridge` 登记为独立实例；隔离启动以一次性 URL 提供关联提示；URL 到达不证明该窗口拥有独立 profile，可能被浏览器转交原有窗口。Broker 仍须核验存活进程及真实 profile 归属后接受自有连接，worker 不替代这项核验。配置只选择连接和身份，不开启未编译的 transport，不代替用户安装、重载或调试权限。独立 SDK 代理的既有连接配置仍属于兼容入口，不与插件实例登记混为一谈。

## 服务、监听和连接是不同状态

首次 `start()` 安装服务、默认命令、转发和生命周期监听，连接浏览器 upstream；重复调用会再次尝试保活和客户端轮询，不重复建立完整服务注册。浏览器启动、安装和 tab 创建等事件会触发该入口。一次入口被调用并不表示每个异步启动步骤都成功；连接状态仍要由实际 peer 和命令确认。

服务使用 offscreen document 与命名 runtime port 发送 keepalive，尽量维持 worker 活跃。offscreen 能力可能不存在或创建失败；保活是运行机制，不是 worker 永不退出的承诺，也不是 ReverseWS 永久在线的证明。worker 重建、扩展重载或连接断开后，远端应重新建立所需的配置与会话。

## 配置和可观测性的边界

共享 server 是 `Mod.configure`、命令注册与 middleware 的权威执行者。状态页只是它的消费者；页面展示不能代替协议握手和真实请求成功。生命周期变更应同时检查 entry、server、offscreen 与 manifest，使资源路径、消息/port 名称及权限继续一致。

插件扩展在登记后、页面选择前，将 Broker 返回的显示编号同时用于 action 数字徽标、标题和设置页；编号分配及非路由身份约束由 `connection/cdphelper-plugin-runtime.mdx` 维护。启动和断线时清除旧显示，登记状态写入与徽标、标题更新沿用同一 stateWrite 队列，避免迟到的登记覆盖断线。徽标或标题失败只报告错误，不能阻断登记状态或自有启动 token 的保留；缺少合法编号时显示暂无编号，不从页面标题、URL 或其他身份推导编号。

工具栏徽标、设置页和接管栏共享按编号确定的背景与文字配色。设置页及接管栏用网页内的圆角色块呈现编号；工具栏原生徽标只设置背景与文字颜色，形状由浏览器渲染。断线或编号不可用时移除旧编号色块，不能让旧显示继续代表当前连接。

bridge 的结构化登记错误沿用同一状态写队列写入 session storage，清除旧徽标，并在随后断线通知中保留具体组件与原因；下次成功登记才清除错误。扩展身份、协议和 Release 版本拒绝由插件 bridge 分类，worker 只保存并展示，不把拒绝当作正常登记、不自动安装或重载扩展。

构建和重载没有跨 worktree 自动同步机制。运维成功条件是预期目录中的新扩展已装载、所选 downstream 已建立 peer，并且实际命令可用；仅有新 ZIP、状态树或监听端口不能满足这些条件。
