# 面向普通 CDP 客户端的扩展入口

修改桥接前先阅读 transport 所有者，区分 listener、peer、pending 请求与消息来源；这些前提决定此处的持久连接和断开语义。

Node 代理将普通 CDP WebSocket 与共享扩展服务连接，浏览器 adapter 在 `chrome.debugger` 能力范围内提供 browser target 和 flattened session。它使禁用了对外 CDP 接口的浏览器可复用标准客户端；它不创建完整的原生浏览器 CDP，也不能绕过扩展安装、调试权限或目标可见性限制。

## 两层生命周期

普通代理连接为每个前端构造客户端，按 launcher 配置连接或启动浏览器。已有浏览器模式使用 `launcher=none` 和 `upstream=reversews`：代理先建立反向监听，并在整个代理生命周期保留同一个扩展 peer，包括没有前端的时候。

多个 CDP 客户端只支持顺序接入：持久模式只允许一个 CDP 前端同时连接，第二个并发连接被明确拒绝。这个并发限制属于代理的前端会话所有权，支持顺序连接不代表并发隔离。前端断开会取消桥接请求并通知扩展重置 adapter，保留 ReverseWS 监听和独立运行的浏览器。代理整体退出才释放它拥有的连接资源。

断开通知是 ReverseWS bridge 的私有生命周期消息，不属于公开 `Mod.*` 命令。扩展等待在途请求后 reset，后续请求等待 reset 完成；公开前端 session 状态不能跨连接继续使用。

HTTP discovery 返回的是代理合成的 browser endpoint，不是真实页面列表。`/json/version` 成功只证明监听可用；扩展连接、配置握手和目标操作仍可能失败。

程序化代理可选择配置 `proxy_client_token`，对 HTTP 与 WebSocket 升级请求校验 token 并拒绝网页 Origin。独立代理默认行为保持兼容；cdpHelper 插件必须设置此凭据，并由 Broker 用返回的带 token WebSocket 地址连接 Playwright，避免其他本机客户端绕过插件会话占用。

## 保持线序而不是重新调度

持久桥接给前端请求分配独立的负 ID，代理内部请求使用自己的 ID 空间，收到响应后还原前端 ID。响应和事件按 upstream 接收顺序转发；不能把响应改为等待 typed `send()`、同时同步转发事件，否则 Runtime 事件可能越过 frame-tree 响应，使客户端丢失 execution context。

请求超时应返回关联原 ID 与 session 的错误，连接关闭要清除计时器和待处理请求。超时不会证明浏览器命令已取消，也不能自动重试具有副作用的操作。

## Adapter 与原生 debugger 的权责

`ChromeDebuggerCDPAdapter` 拥有合成 browser target、前端会话、发现/自动附加状态和 session 层级。`ChromeDebuggerUpstreamTransport` 拥有原生 debuggee 选择、附加、事件来源及底层命令。两者各自记账，不能用合成 sessionId 直接替代原生 debugger session。

原生 child session 必须与所属 root debuggee 一起使用。OOPIF 缺少 parentFrameId 时需先读取真实 child frame tree 再发布 attached 事件；不能用虚构父 frame 或提前事件填补客户端的 frame graph。

目标刷新必须把快照、附加和差异发布串行处理，避免旧快照撤销较新刷新刚建立的页面会话。chrome.debugger 目标列表在导航期间暂时缺项，不等于普通标签页已经关闭；保留经 tab 身份核对仍存活、仍属于可操作 URL 的已知目标，枚举恢复后复用原有公开会话。真实 tab 删除或原生 debugger detach 仍须使对应会话失效，不能为容忍枚举间隙而保活已关闭页面。

只支持 flattened attach。普通 profile 中可见且可调试的 tab 和引擎允许的子目标可进入此模型；内部页面、隔离 browser context 和任意 browser-scoped 命令不因代理存在而变得可用。未知 session 和不支持的浏览器命令要明确失败，不能伪造成功结果。

Target.createTarget 的 background 参数经 adapter 传到原生 tabs.create 的 active 选项；background=true 才后台创建，未指定时保留普通客户端原有的前台创建语义。Target.activateTarget 仍是显式激活请求，不能伪装成后台成功。cdpHelper 插件负责在正常任务中选择后台建页并避免主动激活，扩展的 activeTab 权限不是标签页激活开关；后台能力不能靠删除该权限取得。

同一原生页面可对应多个公开 CDP session，原生调试域状态仍共享，事件按各公开 session 路由。插件的页面提示、性能采样与 Trace 可以复用页级 session，但不能假定它们是隔离的 native debugger，或在私有功能结束时随意发送 Network.disable、Runtime.disable、改写自动附加配置。脱离某个公开 session 也不能解除仍由其他公开 session 使用的根附加。

页面级 Network、Performance、Tracing 等命令经页 session 转发；browser target 只提供有限补齐的能力，不能因为协议类型存在就改从 browser session 调用。Trace 的实际引擎支持、完成事件及 IO 导出必须越过扩展代理验证。浏览器原生扩展 debugger 提示可能全局显示，不可据此推断 Broker 已绑定每个页面；插件自定义接管状态由会话资源所有者维护。

调试附加还区分 owned 与 borrowed。重置优先解除本 adapter 拥有的根附加，以释放暂停子目标；借用的连接只做必要恢复。不要在解除根附加前逐页等待 Runtime 调用，否则失去响应的 renderer 会拖住清理和后续连接。原生层遇到“已被附加”时必须证明当前扩展确实能使用该会话，不能吞掉其他调试器占用错误。

## 客户端与验收边界

Playwright 的 `connectOverCDP` 使用 `noDefaults: true`，避免默认初始化依赖本入口没有的 browser-level 能力。关闭该选项不仅恢复焦点模拟，还改变下载和媒体初始化；Browser.setDownloadBehavior 不属于当前扩展入口支持的浏览器能力，不能直接全局放开或为通过连接而伪造成功。插件按受控页面启用及清理所需焦点模拟，其授权生命周期和视口截图策略由 `connection/cdphelper-plugin-runtime.mdx` 维护。

优先复用默认 context；此入口不提供 Playwright 隔离 context。cdpHelper 插件的 isolated 模式请求启动独立 profile，以一次性 URL 关联手动加载的 Release 扩展；URL 不证明真实隔离，是否存在匹配 profile 的进程须由插件运行时核验，当前仅 Windows 实现该核验；它仍使用 bridge，不要求原生 CDP 端口开放。多 profile 统一登记入口不是多个 CDP 客户端直接共享代理的授权；插件会话和 tab 独占由 `connection/cdphelper-plugin-runtime.mdx` 维护，不改变代理单前端限制。

版本信息只能从当前环境取得，扩展无法获得的 revision 和运行时版本保持未知，不能借用其他安装的浏览器值。

验收应依次越过监听、ReverseWS peer、扩展配置、普通页面 evaluate/DOM 和所需的截图或性能采集边界。某个已验证客户端操作不代表其他 CDP 工具和所有命令都兼容。已有浏览器的真实验收与独立测试浏览器回归必须分别报告，不能互相代替。
