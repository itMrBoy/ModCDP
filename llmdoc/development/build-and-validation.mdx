# 构建产物与验收边界

适用于改动浏览器扩展、代理启动入口、SDK 分发或发布流程。命令和版本以 `package.json`、各语言 manifest 与 README 为准；这里维护容易在重复操作中破坏的构建顺序和成功判据。

## 选择并完成同一种构建

Node 工具链生产各语言共用的浏览器端服务。普通安装通过 `prepare` 执行构建；不要新增再次调用安装的 `install` 生命周期入口。构建中的 Python README 步骤只检查文件存在，不要求 Python 运行时。

先决定是否需要扩展主动连接 ReverseWS 或 NATS。它们是资源编译时开关，普通 `build` 会关闭，并不是可以经 `Mod.configure` 随时开启的服务器配置。

已有浏览器启动入口必须先完成普通构建，再以 ReverseWS 开关重建扩展资源，最后直接执行构建后的代理 CLI。若最后改为再次调用会执行普通构建的入口，刚选定的开关就会被覆盖。快捷入口应复用根脚本，避免 Paseo 与命令行各自维护一份参数。

资源脚本从同一次构建产生 `dist/extension` 与 ZIP，并把归档复制给 Python、Go 包。构建不是事务：编译或归档失败后，不应发布部分更新的目录或新旧混合的 ZIP。修复后重新完成整条链；跨平台归档字节也不保证完全相同。

## 对齐实际加载位置

浏览器必须加载当前 checkout 的 `dist/extension`。源码目录 `extension/` 不可替代可加载产物；重建也不会更新另一 worktree 已装载的目录。

构建脚本不 watch、不自动重载扩展。资源改变后应重载实际装载的扩展，并重新建立连接。发布或打包 SDK 前，核对加载目录、归档及两个语言包副本属于所选构建，避免把本地可选连接方式作为默认产物分发。

ZIP 同步仅证明共享浏览器端服务一致，不能证明三个客户端 SDK 的能力或原生传输实现一致；语言维护边界见 `development/sdk-parity.mdx`。

## 验证到所需责任边界

选择与改动相关的静态检查和真实链路测试。测试浏览器、用户已运行的浏览器、云端浏览器及原生宿主具有不同前提；一类测试通过不能替代另一类验收。端口可访问只证明入口存在，页面操作必须越过扩展连接、权限和目标会话边界。

完整测试有固定资源和外部服务依赖。CI 将语言组、连接器与反向连接组分开调度；本地执行也要避免冲突，不能仅以一个通用命令推断全部能力已覆盖。正常 hooks 保留；未安装 hook 时应明确说明实际手动执行的检查。

发布工作流只拥有 npm 分发，且受仓库和触发条件约束；它不自动发布 Python 或 Go 包。不要用发布动作验证本地改动。最终报告应分别说明构建成功、自动回归和真实浏览器验收的范围，留下未满足的外部前提。
