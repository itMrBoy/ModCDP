# JS SDK 与协议生成维护

仓库仅维护 JS SDK、Node 代理及浏览器扩展；Python/Go 实现、测试、分发包和跨语言同步义务已移除。修改协议前先阅读命令执行所有者，确认 registry、线格式与特权表达式的权威边界。

## 公开入口与运行时能力

公开入口不只是别名清单，还注册 launcher/injector 构造器。直接导入内部客户端与经公开入口使用可能具有不同的模式可用性；变更注册方式或默认入口时，应同时验证模式解析和构造器装配。

JS 使用 Zod 维护运行时 schema。类型声明、schema 序列化及实际校验须保持一致；只改变类型不能证明运行时协议兼容。SDK、插件 Broker 与扩展服务分别拥有自己的生命周期，打包在一起不等于可以相互代管清理。

## 生成物的权威来源

codegen 从 `devtools-protocol` 生成标准 CDP 类型、运行时 schema 和调用别名，扩展的 Mod 类型来自手写协议定义。生成版本从既有生成头恢复；更换协议输入是明确维护决策，不能手改生成体掩盖差异。

普通 build 编译和打包已有协议面，不运行协议生成器。类型可用、schema 识别和浏览器实际支持是三件事；新增别名或生成标准命令不会扩大扩展调试权限或 browser-level 能力。标准 CDP 与 Custom/Mod 的执行及局部校验豁免由 `protocol/command-execution.mdx` 维护。

manifest、导出和测试是当前能力的权威来源；这里不维护版本表和生成文件清单。对齐结论须指出被验证的实际调用链，不能把 SDK、插件或某浏览器上的成功外推到所有接入方式。
