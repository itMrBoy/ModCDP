# cdpHelper 插件的会话与资源权属

Codex 与 Claude Code 共用本地 MCP 工具及 Playwright。技能负责用户选择和使用流程；本页维护实例登记、会话及 tab 权属、断连与清理边界。源码仓不充当安装产物；用户安装 cdpHelper main 的 marketplace 与完整插件。ModCDP 从根目录 cdpHelper 子模块锁定分发提交，分发仓不引入源码；产物通过构建元数据记录源码提交，具体交付顺序由构建指南维护。

## 宿主入口与命名空间

Codex 兼容清单显式声明技能与专用 MCP 配置；portable 根清单的 OpenAI extension 保持对应配置。Codex 的入口和 cwd 按已安装插件根目录解析，不能假定其会展开 Claude 的插件变量。Claude Code 使用自己的 .mcp.json 配置。三份 MCP 配置统一使用 cdphelper 作为 server key。

宿主验收必须分别检查技能发现与 MCP 连接；Codex 可能按插件命名空间返回 cdphelper:cdphelper，用户级安装为 scope:user，不能只按未限定技能名精确匹配。SDK 直接启动运行时的成功结果不能代替真实宿主对清单、路径和变量的解析验收。

MCP 工具对外的参数 Schema 与服务端校验可以分开维护：Claude API 不接受根级 oneOf、anyOf 或 allOf，不能依赖宿主转换，否则可能只丢失某个工具而其他工具正常。browser_select 对外以普通 object 公布 mode 与两种模式的字段，并在说明中声明参数组合；服务端仍严格校验 reuse 必须提供实例 UUID、isolated 仅允许可选 executable，禁止两种模式混用字段。压缩产物的 tools/list 回归须检查根级 Schema 兼容，SDK 能列出工具名不代表 Claude 最终能使用该工具。

标识统一使用 cdphelper，展示名称为 cdpHelper；技能正文仍可保留当前内部雪诺浏览器操作说明。插件命名不意味着浏览器兼容范围扩大，实际雪诺隔离仍受下文进程归属核验和真实验收限制。

运行数据写入 ~/.cdphelper；旧 ~/.snow-browser 原样保留，不自动迁移浏览器实例或清理 profile。新服务不根据旧目录记录取得浏览器控制权。

## 一个后台服务，多个登记实例

MCP stdio 握手与工具发现先于后台就绪，不因旧后台阻塞而让整套工具消失。`runtime-client.mjs` 为每个接入管理后台连接和独立会话，同一用户目录复用一个 Broker。`browser_status` 分别报告宿主已加载插件、本机后台及目标版本；后台不可查询时 `instances: null` 表示未知，不能作为空清单处理或借新建隔离实例绕过故障。stdio 只承载协议，日志独立保存。入口使用 Node ≥22 和完整随包依赖，不下载依赖、不切换 Node 或修改 PATH，也不通过缓存复制修补不完整产物。

后台版本较旧时先返回 `upgrade_required`，Agent 必须告知具体 plugin 版本及旧控制、诊断中断影响，再回传本次 `upgrade_notice_id` 作为 `acknowledge_upgrade_notice`；它记录告知已完成，不代替页面选择或清理同意。提示凭据仅在当前 MCP 接入内关联后台 PID、runtime 与私有 token，状态输出不泄露 token。确认立即返回 `upgrading`，后台异步交接；Agent 按返回间隔有界轮询，不能重复提交提示或重放页面操作。交接使旧会话、控制代次及页面引用失效，清理自有提示和采集，保留宿主、浏览器窗口、标签页与 profile；已发出的操作可能继续产生效果。

启动锁内重新核对被告知的后台快照与已激活版本下限，防止陈旧确认、并发替换或旧宿主重新启动低版本后台。同版本不同摘要拒绝接管。支持升级协议的后台先协作退出且有退出预算；旧协议后台仅在 Windows 核验自有运行时目录、构建身份、Node executable 和完整 daemon 参数后才允许定向终止，验证失败不杀进程。任何交接都不关闭宿主或浏览器。宿主加载版本落后于已激活后台时返回 `plugin_reload_required`，明确要求重载对应 Codex 或 Claude Code 的 plugin 配置，不支持时退出重开该宿主；MCP 重连可能继续沿用旧路径，不能等同插件配置重载。

定向终止自有 Node 后台仍可能连带结束它启动的浏览器。Windows 的 libuv 将非 detached 子进程纳入父进程私有的 kill-on-close Job Object，`unref()` 不能解除该关系。隔离启动通过 `spawnIndependentBrowser` 使用 `detached: true`、忽略 stdio 并 `unref()`，同时保持 GUI 可见；记录与 owner marker 同时保存 `lifetime_detached: true` 作为启动证明，不能仅按 plugin 版本推断。

新启动方式不能追溯解除旧窗口的父进程依赖。启动锁内的 `assertBrowserLifetimePreserved` 先于升级 RPC 和进程信号检查旧隔离记录；仍存活且没有双份 detached 证明，或归属、记录及进程状态无法核验时，以 `PLUGIN_BROWSER_PRESERVATION_BLOCKED` 阻止交接，`browser_status` 返回 `upgrade_blocked`。Agent 保留旧后台和窗口，明确旧/目标 plugin 版本及原因，不自动重试；待用户主动结束这些旧隔离窗口并明确继续后再交接。已退出的旧实例可放行，用户自行启动的 reuse 窗口不受此保护阻塞。旧后台的正常退出也有同一进程寿命风险，不能把“没有直接结束雪诺 PID”当成窗口保留证明。

运行时与固定版本生产依赖以 runtime.pack.gz 随包交付，插件 Git 树不包含展开的 node_modules。入口使用 Node 内置能力先校验外层产物，再按内部 runtime inventory 核验文件路径、内容与权限，并限制解压大小；首次运行只在用户运行时目录内物化文件，完整验证后原子启用，后续仍校验缓存。缺失或校验失败须报告，不能联网补装或跳过校验。依赖在本机缓存展开是运行准备，不代表将依赖目录提交到仓库。

多个普通 profile 统一通过 127.0.0.1:29393/bridge 登记为独立实例；公共监听入口不等于共用实例身份。每个 profile 的连接身份保存在自己的扩展 storage 中。`plugin/src/bridge.mjs` 拥有29393监听、扩展 Origin 与 hello 协议/版本核验，以及每个 peer 到各自认证代理的 relay；这些职责不下沉为普通页面权限。用户从独立 Release ZIP 自行安装扩展，插件不接收目录、不下载或复制扩展、不提供 configure_extension，不向公共扩展目录写入凭据。

登记拒绝区分扩展身份、桥接协议与配套 Release 版本，不能一律解释为扩展未连接。bridge 只保留短期、有界且脱敏的拒绝摘要，不记录原始 hello、启动 token、名称或网页信息；Broker 状态可在实例未登记时报告这些问题。扩展版本落后时 `extension_update_required` 指向浏览器扩展手动更新；扩展较新时 `plugin_update_required` 指向对应宿主的 plugin 更新或配置重载，不能要求降级扩展。身份及协议错误沿用各自恢复动作，不将任何拒绝记录视为可选实例或控制授权。

Broker 为所选实例持有唯一 Playwright 连接，多会话共享该连接。底层代理单个 CDP 前端的限制仍然成立；插件通过内部调度和 tab 归属提供多会话，不能由此推断独立代理支持多个 Playwright 客户端。IPC 和 CDP 前端保留身份校验；扩展登记及启动关联同样必须落在预期本机信任边界，不能用浏览器 UA 或端口监听代替 profile 身份。

会话操作顺序执行，不同会话的不同 tab 可以并行。同一 tab 绑定实例且由一个会话独占，其他会话只能看到 busy。新 tab 自动归创建会话，释放会话结束其页面控制与采集，不关闭用户浏览器或页面。页面内容不是新的操作授权。

## 页面控制与人工停止

Broker 的 tab 归属是操作授权，Playwright 的底层 debugger 附加不是。Playwright 负责操作和观察页面，ModCDP 补齐扩展调试通道与标准 CDP 客户端的差异，插件负责将能力包装成 MCP 工具、资源归属和可查询结果；新增工具优先复用现有连接，只在测试证明协议缺口后修改适配层。

每次绑定具有独立控制代次。工具入队时记录代次，执行前再验证，释放或重新绑定不能复活旧队列。页面内接管栏、目标轮廓和真实鼠标事件提示仅随绑定生命周期存在；安装失败回滚绑定，导航后重建。提示层运行在独立 world，以 closed Shadow DOM 隔离页面样式，正文快照不把它当作业务内容。页面提示不同于浏览器原生全局 debugger 提示，也不能替代 Broker 的授权校验。

接管 UI 由 plugin 注入，扩展只桥接调试通信，网页点击仍由 Playwright 执行。提示层的被动显示穿透指针，只有“停止控制”按钮接收事件；接管栏按当前操作目标框避让，不改写源站布局或样式。点击目标先通过 Playwright 滚入视口，再测量并更新提示位置，继续使用普通 locator 点击和命中校验，不以强制点击、页面脚本点击或禁用停止入口绕过遮挡。closed Shadow DOM 内的停止按钮被命中时，错误可能只报告外层控制 host，不能据此判断整屏透明层都在拦截。

人工停止通过页面专用 Runtime binding 通知 Broker，验证来源执行上下文、随机凭据和控制代次，不等待普通工具队列。Broker 先撤销归属、更新代次并中断本地等待，再清理提示及采集；其他页面和会话不受影响。普通重新绑定不能越过用户停止标记，只有用户明确要求恢复后才可使用恢复确认参数。已经发送的操作和脚本可能继续产生副作用，本地停止不等于浏览器回滚，不自动重试未知结果。

提示层必须在释放、页面关闭和断连后清理。新文档注入和现有文档提示都有有效期，后台失联不能让旧控制标识无限存活；不能为清理插件私有脚本而关闭 Playwright 共用的调试域。

## 页面脚本与诊断数据

通用脚本仅在已绑定 HTTP(S) 页当前主 frame 执行，函数源码不在 Node 或扩展后台求值，不提供跨导航自动注入。它具有网页本身的能力，包括读写页面、登录态请求及网页已暴露的桥接对象，不能把只读声明或隔离 world 当作副作用隔离。工具按可能修改数据的操作声明。结果仅返回有界 JSON；超时只结束本地等待，不保证终止脚本，也不承诺清理任意用户脚本创建的监听。

网络与 Console 优先监听现有 Page 事件，先开始采集再复现；开始前的完整历史不可恢复。采集记录归创建会话，释放或断连后停止读取 live page，但存续会话仍可查询已收集的数据。网络耗时基于完整请求生命周期，重定向保留关联，完成、失败与挂起分开；未知缓存来源及缺失耗时明确标注，不凭零值猜测。正文按需读取，受引擎保留及大小限制，无法获取不伪造空正文。

顶层文档性能记录按 time origin 区分导航，内部 PerformanceObserver 与导航脚本必须可移除；不可用、暂定或截断的指标不能报告为最终完整值。采集内存、记录条数、采集窗口和结果大小均有上限，达到限额只能按声明淘汰已停止数据或标记丢弃，不能静默声称完整。可变工具参数及具体限额由源码 Schema 和共同技能维护。

性能 Trace 从绑定页内部 CDP session 发起，锁归浏览器实例而非单个 tab。只有成功开始录制的会话能停止自己的录制，不能抢停外部或其他会话；启动在途遇到释放时，待启动完成后收尾自有录制。停止请求、完成事件、IO 流读完和文件完成是不同状态；导出异步执行且有文件上限，失败、超限或断连均不得报告完整。录制可能包含共享进程活动，不承诺严格只含绑定页；这是 DevTools 性能 Trace，与 Playwright 测试步骤归档不同。导出写入专用诊断目录，返回绝对路径和完整性信息。

## 每会话明确选择实例

首次浏览器操作必须先 browser_status 列出 inventory 的名称、display_number 及状态，再在同一问题提供已有实例与新开隔离选项，不能先泛问 reuse/isolated 再查询清单。未选择时页面工具拒绝操作，不设置隐式默认或失败 fallback。显示编号映射到当次 inventory 中完整的 instance_id UUID，不能把编号作为路由 ID、要求用户查找 UUID，或用唯一一个在线实例替代用户的选择；识别实例不额外读取页面标题或网址。

Broker 为每个成功登记的连接分配 display_number，后台生命周期内从 1 递增，断连不复用、重连换号，后台重启后重新计数。因此编号不是持久身份，也不改变旧引用失效和重连后明确选择的规则。registration 与 browser_status instances 返回同一编号；默认名称为“浏览器 N”，自定义名称可以重复，由编号区分。同一 profile 的多个窗口共用其扩展连接及编号。扩展登记后即可显示同号徽标和设置页，用户固定到工具栏后可对照徽标，未固定时查看设置页；显示不需要先选择或操作页面。

接管栏的编号由 Broker 从当前绑定实例传入，与工具栏和设置页沿用同一编号及配色；未知编号不伪造默认值。色块用于辅助识别，不能只凭颜色选择实例，也不改变编号与连接 UUID 的分工。

编号作为协议 2 登记消息的可选 display_number 扩展，解码继续接受未含编号的旧消息；不新增 MCP 工具，也不把显示信息当作身份或隔离核验依据。扩展显示状态与失败处理由 worker 生命周期所有者维护。

reuse 选择已登记普通 profile，沿用其登录状态和 cookies；同一 profile 不隔离账号。isolated 请求启动实际雪诺的独立 profile，通过一次性启动关联 URL 将对应扩展首次登记与本次创建关联，不复制现有 profile，也不依赖原生 CDP。找不到雪诺、扩展未安装或关联失败时明确报告，不切换其他 Chromium 或复用实例。

隔离启动必须显示供用户安装扩展和操作的 GUI 窗口；进程归属与窗口可见性分别验收，不能只凭进程存活或事后恢复隐藏窗口宣称新启动流程通过。

启动 nonce/URL 只表示请求归属，不能证明收到 URL 的浏览器仍是独立 profile。雪诺可能退出新进程或合并到原有窗口；带 nonce 的接入必须经 isolatedRunning 核验存活进程的真实 executable、精确 profile 参数及目录/owner marker。每次自有实例页面动作前重新核验，失败 detach、使引用失效且不发送页面操作，不自动转为 reuse。核验目前仅在 Windows 实现，非 Windows 明确返回 false；隔离只能在可验证环境尝试，不承诺实际雪诺支持，复用模式不受影响。

pending 提供 launch_process_running 与 waiting_for_extension/launch_exited_unverified，区分已核验进程仍等扩展和进程退出、合并或不可验证。后一状态须明确报告隔离未建立，并按用户意愿保留或清理后才重试。不能把等待扩展与已建立隔离混为一谈。

监听、profile 登记、所选实例连接和 Playwright 页面可操作是不同状态。用户仍需在目标 profile 手动安装/重载 Release 扩展；同一份扩展文件可供多个 profile 加载，配置位于 profile storage。profile 隔离不承诺隔离雪诺原生账号或系统凭据。

隔离实例的所有权记录 ID 稳定，但每次扩展连接均分配新的连接 UUID；连接重建不是同一选择的延续。inventory 的 instance_id 用于当前连接选择，owned_instance_id 指向隔离所有权记录，retained 的 instance_id 用于清理，不能互换。

## 断线、退出与清理

扩展失联、页面关闭或切换实例后，旧 tab 引用失效；重连不自动恢复归属，也不自动 rebind。重新读取 inventory，由用户明确选择实例，再发现和绑定页面。超时或断线不能触发有副作用操作的自动重放，必须先核对实际结果。

客户端退出、心跳失联或后台空闲回收只释放会话、连接及服务资源，不自动关闭用户窗口或删除隔离 profile。保留记录不证明浏览器仍存活，也不表示已获下次清理同意。stdio 入口收到 EOF、SIGINT 或 SIGTERM 时，先释放会话，再关闭 MCP server/transport，让事件循环自然退出，避免 Windows Node 尚在关闭句柄时强制 process.exit；错误写标准错误和退出码。

通过 `connectOverCDP` 建立的 Playwright 浏览器句柄在释放时关闭调试连接；不能因 `browser.close()` 的名称推断它关闭远程雪诺，更不能通过删除正常连接收尾来修复 Windows 子进程寿命问题。扩展失联时先核验对应浏览器是否仍运行；进程已退出不能继续解释成等待扩展重连，profile 目录存在也不等于窗口保留。

Bridge 关闭先停止接入并解除自有连接，再回收本服务的 HTTP 连接；不能等待浏览器初始化页或预连接补齐请求头后才退出，也不因此关闭浏览器或标签页。

离开 isolated 实例前必须询问是否关闭并清理；仅有用户明确同意才执行。清理先核验目录边界和 owner marker，再核对实际进程身份，确认退出后才删除。Windows 先请求关闭窗口，必要时只停止再次核验匹配的自有进程，不直接终止记忆中的 PID。其他平台仍在运行时提示手动关闭后重试。核验使用有超时上限的异步进程调用，不阻塞 Broker 心跳及其他会话。

未答复、拒绝或异常断开均保留窗口与 profile；失败保留记录并报告阻碍。reuse 永远不取得用户原有浏览器和 tab 的关闭权。确认字段只能反映真实答复，不能将无答复当作同意。
